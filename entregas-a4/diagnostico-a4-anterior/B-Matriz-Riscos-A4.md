# B. Matriz de riscos A4

Escala: CRÍTICA = cenário de perda de bases sem proteção suficiente; ALTA = conflito/duplicação/estado incorreto com impacto nos registros; MÉDIA = inconsistência de fluxo/desempenho; BAIXA = ajuste de interface sem escrita de dados. Prioridade é avaliação técnica, não frequência reproduzida. Os dez IDs D-A4 são registros novos desta análise, sem substituir os originais.

| ID | Prioridade | Estado | Escopo / IDs originais | Risco |
|---|---|---|---|---|
| D-A4-01 | **CRÍTICA** | ✗ Problema identificado | A4 com dependência de A5; P0-3; AJ-18; B-102 (relação, não reprovação nova) | Uma aba antiga pode mesclar a partir de um cadastro anterior e apagar mudanças clínicas de outra aba. Interrupção entre chaves pode deixar estado parcial. São cenários inferidos do código, ainda não reproduzidos nesta análise. |
| D-A4-02 | **ALTA** | ✗ Problema identificado | A4 histórico; P0-3; A1-45; B-120; B-121; AJ-8 (referência textual) | Livro antigo permanece na tela; gravação seguinte é recusada pela proteção. No clínico, o token esperado também fica anterior ao merge da própria aba, causando recusa. Não remover essa recusa para disfarçar o sintoma. |
| D-A4-03 | **ALTA** | ⚠ Necessita revisão | A4; decisão funcional; P0-3 (família); sem ID histórico específico para esta ampliação | Possível duplicação semântica de valores; vínculo de novos pagamentos/evoluções a um paciente de mesmo ID e conteúdo incompatível. Não é prova de exclusão de um registro já gravado. |
| D-A4-04 | **ALTA** | ✗ Problema identificado | A4 com contrato A5; B-119 (restauração, escopo distinto); B-120 (merge legado) | Incompatibilidade operacional, linhas inválidas persistidas até futura leitura/quarentena, perda de significado da cobertura e de integridade do arquivo. A5 ler/restaurar legado não significa que o merge também o aceite. |
| D-A4-05 | **ALTA** | ⚠ Necessita revisão | A4; integração/proveniência transversal; P0-4 (algoritmo, não a política); sem ID histórico específico para este risco | Campos manuais de outras origens podem não ser reconhecidos como manuais; homônimos sem CPF podem parecer compatíveis. Há proteções existentes que precisam ser preservadas. |
| D-A4-06 | **ALTA** | ✗ Problema identificado | Transversal relacionado a A4; P1-3; A1-40/41/42/43; C-46 (regressões do livro) | Visões antigas, último escritor vencendo em bases sem proteção e possível corrida entre duas comparações aprovadas. Guard de epoch e exclusividade de restore não são serialização universal de edições comuns. |
| D-A4-07 | **ALTA** | ✗ Problema identificado | Transversal UI/persistência; A1-56/57 (regressões já protegidas no livro); P1-3 (relação) | Tela pode mostrar estimativa/progresso não salvo; exportação específica pode divergir do backup v3 que lê o armazenamento. Não significa que o backup unificado exporte esse cache: A5 lê a base persistida. |
| D-A4-08 | **ALTA** | ✗ Problema identificado | A4 de projeções; módulo Academia/Laboratório; Sem ID histórico específico; BKP-08 é outro problema | Progresso importado pode não aparecer e uma interação posterior pode regravar o subcampo com estado antigo da própria página, mesmo com token do pai atualizado. Cenário necessita teste independente. |
| D-A4-09 | **MÉDIA** | ✗ Problema identificado | A4 visual/fluxo; A1-45 (projeções); sem ID histórico específico para mês/navegação | Filtro pode ocultar registros importados ou seleção representar cadastro antigo. Refresh indiscriminado pode apagar um formulário não salvo. Parte da diferença pode ser intencional. |
| D-A4-10 | **MÉDIA** | ⚠ Necessita revisão | Desempenho transversal, não A4 exclusivo; P0-4; PERF-01 | Bloqueio da interface e maior intervalo entre leitura e ação; avaliações antigas não medem a DEV.4. Não transformar otimização em alteração da identidade dos pacientes. |
| UX-A4-01 (proposta, não defeito auditado) | BAIXA | ○ Pendente | Interface | Rótulos de origem/revisão, acessibilidade e explicação do filtro. Se alterarem formulários ou escrita, reclassificar como MÉDIA/ALTA. |

Há uma prioridade CRÍTICA, sete ALTAS e duas MÉDIAS. As proteções existentes reduzem alguns cenários, mas não autorizam concluir ausência de perda em todos os escritores. Nenhum risco foi reproduzido com pacientes, importações ou navegador nesta etapa.
